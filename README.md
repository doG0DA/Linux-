# Эмулятор командной строки

Практическая работа по дисциплине «Конфигурационное управление», РТУ МИРЭА, вариант 12.

Консольный эмулятор оболочки UNIX-подобной ОС на Java. Приглашение к вводу собирается из данных реальной ОС: имя пользователя и имя компьютера. Если VFS загружена, в приглашении показывается текущий каталог VFS, иначе текущая папка ОС (домашняя заменяется на ~).

## Параметры запуска

```
run [--vfs <путь к VFS>] [--script <путь к стартовому скрипту>]
```

--vfs задаёт путь к физическому расположению VFS, --script путь к стартовому скрипту. При запуске все параметры выводятся в отладочном виде. На неизвестный, повторный или пустой параметр выводится ошибка.

Стартовый скрипт это текстовый файл с командами эмулятора, по одной в строке. Пустые строки и строки, начинающиеся с #, пропускаются. Каждая команда выводится вместе с приглашением, как будто её ввёл пользователь. Выполнение останавливается на первой ошибке с указанием номера строки, после скрипта эмулятор переходит в интерактивный режим.

## VFS

Виртуальная файловая система загружается из XML-файла, заданного параметром --vfs, и дальше живёт только в памяти: файл на диске не изменяется. Корневой элемент vfs с атрибутом name (имя VFS), внутри элементы dir и file с обязательным атрибутом name и необязательным owner (по умолчанию root). Текст элемента file это содержимое файла, общий отступ строк убирается. Для двоичных данных указывается encoding="base64".

```xml
<vfs name="example">
    <dir name="home" owner="yura">
        <file name="hello.txt" owner="yura">Hello, world!</file>
        <file name="logo.bin" encoding="base64">iVBORw0KGgo=</file>
    </dir>
</vfs>
```

Если файл не найден или имеет неверный формат (битый XML, другой корневой элемент, неизвестный элемент, повторяющееся имя, неверный base64), выводится ошибка, и эмулятор работает без VFS. Примеры лежат в examples/vfs, ошибочные в examples/vfs/bad.

## Разбор команд

Строка делится на слова по пробелам. Переменные окружения ОС раскрываются в формах $ИМЯ и ${ИМЯ}, несуществующая переменная заменяется пустой строкой. В двойных кавычках пробелы сохраняются, а переменные раскрываются, в одинарных текст берётся как есть.

## Команды

ls и cd пока заглушки и выводят своё имя и аргументы. cd принимает не больше одного аргумента.

exit [код] завершает работу с указанным кодом (по умолчанию 0). Код должен быть числом.

conf-dump выводит параметры эмулятора в формате ключ=значение.

vfs-info выводит имя загруженной VFS и хеш SHA-256 данных её файла.

На неизвестную команду и неверные аргументы выводится сообщение об ошибке.

## Сборка, запуск и тесты

Нужен JDK 17 или новее. На Windows используются .bat, на Linux и macOS .sh.

Тесты написаны на JUnit 5 и лежат в папке tests. test.bat при первом запуске скачивает JUnit в папку lib (она не хранится в репозитории), компилирует проект с тестами и запускает их. В IntelliJ IDEA тесты можно запускать кнопкой рядом с классом, подключив JUnit 5 через Alt+Enter на аннотации @Test.

```
run.bat --vfs examples/vfs/deep.xml --script examples/scripts/stage3.txt
test.bat
```

В папке scripts лежат скрипты ОС, которые запускают эмулятор с разными параметрами: stage2_no_params, stage2_params, stage2_bad_params, stage2_script_errors (параметры и стартовый скрипт), stage3_vfs_variants и stage3_vfs_errors (разные варианты VFS и ошибки загрузки). Стартовые скрипты эмулятора лежат в examples/scripts.
